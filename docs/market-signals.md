# Minute market signals

`GET /api/signal?ticker=AAPL` accepts any valid U.S. stock ticker. The browser can refresh it every 60 seconds. The service caches each symbol for at most 60 seconds and returns the market-data observation time, source feed, and next refresh time.

The endpoint uses Alpaca's stock snapshot API. Set `ALPACA_API_KEY_ID` and `ALPACA_API_SECRET_KEY` **on the server only**. `ALPACA_STOCK_DATA_FEED` defaults to `iex`; `sip` needs an Alpaca entitlement. The free IEX feed reflects one exchange, so its volume, quote, and price range are not consolidated market totals. A delayed feed is never promoted to a live recommendation. Do not add these keys to browser JavaScript or commit them to Git.

No credentials means `status: unavailable`, `recommendation: null`, and a clear connection message. Missing fields, invalid prices, stale bars or quotes, feed authorization errors, and provider outages also prevent a recommendation. An inactive market naturally becomes stale. The UI should always display `status`, `asOf`, and `source.feed` alongside any signal.

Directional screens are restricted to the [NYSE regular equity session](https://www.nyse.com/trade/hours-calendars): weekdays 9:30 a.m.–4:00 p.m. Eastern Time, with NYSE-published 2026–2028 holidays and 1:00 p.m. early closes applied. The current minute bar and quote must also be from that session. Outside it, the endpoint returns `status: closed`, a closure reason, and `recommendation: null` for **both** horizons; the home screener returns no rankings. The calendar fails closed for unverified years. Scheduled holidays and hours cannot capture an unexpected exchange halt or closure, so a live market clock and trading controls would still be needed before executing orders.

Every ready horizon includes `validUntil`, the earliest of regular-session close and the minute bar or quote reaching the three-minute freshness limit. The browser must clear the recommendation at that instant even if its next scheduled refresh has not run. Non-ready horizons return `validUntil: null`.

When data is current, `horizons.intraday` compares the latest minute close with the previous daily close, checks that minute's move, measures where it sits in the day's range, and gates on minute dollar volume, spread, and sub-$1 price risk. `horizons.oneWeek` compares the current price with the close five completed trading sessions ago, checks how many of those closing steps rose, and gates on average daily dollar volume, current spread, and price. One-week history is requested from [Alpaca's historical bars API](https://docs.alpaca.markets/us/v1.4.2/reference/stockbarsingle-1); a fresh current quote is still required. A ticker with insufficient history gets no one-week recommendation. The legacy top-level signal mirrors the intraday horizon.

Each horizon returns `buy`, `sell`, or `watch` as a **research screen**, with component metrics and reasons. The thresholds are explicit in `api/signal.js` and have not been validated as a profitable strategy. `score` is a directional display scale, not a probability or return forecast. `confidence` describes feed coverage, not a statistical confidence interval.

When valid, `scenario` shows the **observed past** long move and hypothetical short move minus the current spread and an assumed 10 basis points of slippage on each side. The `buy` gate uses `observedLongAfterCostPct`; the `sell` gate uses `observedShortAfterCostPct`. It excludes fees, taxes, market impact, and short borrowing costs. `scenario.estimatedFutureNetReturnPct` and `metrics.netProfit` remain `null`: this signal endpoint does not use brokerage positions, fills, or account costs and cannot calculate projected or actual account profit. A `sell` screen does not establish that short selling is available or profitable.

This signal endpoint never submits trades. Stonk has a separate live-only options order API with explicit server-side acknowledgement and operator controls; the ticker signal does not invoke it. A production multi-user deployment also needs user authentication, per-user data entitlements, rate limiting, per-user brokerage authorization, risk limits, and an audited execution service before market data keys or orders are enabled for public users.

Sources: [Alpaca snapshot API](https://docs.alpaca.markets/us/reference/stocksnapshotsingle), [Alpaca market-data plans and authentication](https://docs.alpaca.markets/us/docs/about-market-data-api), [Alpaca market-data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq).
